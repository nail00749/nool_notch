# Nool Notch

Нативная macOS-челка для быстрых рабочих действий и фоновой информации.
Она закрепляется по центру верхнего края экрана, раскрывается поверх рабочего
стола и объединяет несколько независимых панелей в одном окне.

## Возможности

- AI-панель с лимитами ChatGPT, Claude Code и Ollama Cloud;
- единый Agent Inbox для Codex Desktop, Codex CLI и Claude Code со статусами,
  запросами внимания, Jira-связями и ответами прямо из челки;
- связанные с AI-сессией PR/MR прямо в строке Inbox: CI, конфликты, reviewer
  activity и переход к MR/PR;
- универсальный Now Playing с обложкой и управлением воспроизведением;
- ближайшие события календаря;
- Jira с личными задачами, переходами между статусами и worklog;
- отдельный Jira-режим `Мои / Закреплённые`;
- закрепление Jira-проектов, досок и отдельных задач;
- настройка внешнего вида компактной челки и запуск при входе в macOS.

В закреплённом Jira-режиме каждый проект или доска отображается отдельным
источником. Для доски загружаются все доступные задачи без фильтра по
исполнителю. Отдельно закреплённые задачи собраны в источнике `Задачи`.

Приложение рассчитано на macOS 14+. Публичный Homebrew-артефакт собирается для
Mac с Apple Silicon. На MacBook используется физическая челка; на внешнем
дисплее или Mac без выреза отображается программный вариант.

## Установка через Homebrew

Публичные сборки пока подписываются ad-hoc и не проходят notarization, поэтому
при установке нужно явно отключить quarantine:

```sh
brew tap nail00749/tap
brew install --cask --no-quarantine nool-notch
```

После установки запусти `NotchApp` из `/Applications` и выдай необходимые
разрешения в System Settings. Homebrew также установит `gh` и `glab`, нужные
панели PR/CI.

Обновление:

```sh
brew update
brew upgrade --cask nool-notch
```

## Подключение Jira

Открой настройки Nool Notch, выбери раздел Jira и укажи:

- базовый URL Jira Data Center или Jira Server;
- Personal Access Token пользователя.

После подключения можно выбрать проекты для режима `Мои`, закрепить общие
проекты и доски, а также добавить отдельные задачи по ключу, например
`NPA-123`. Токен сохраняется только в macOS Keychain.

## Agent Inbox

Раздел `AI -> Inbox` собирает сессии поддерживаемых coding agents в одну
очередь: отдельно показывает запросы внимания, работающие и недавние задачи.
Из карточки можно открыть Codex-задачу, разрешить или отклонить ожидающее
действие и ответить на вопрос, если агент передал варианты или свободное поле.

Если в git-ветке или пути worktree есть Jira-ключ вроде
`NPA-123`, Inbox показывает рядом текущую задачу и её статус. Из карточки можно
открыть Jira, сменить статус или исполнителя, а после завершения сессии — открыть
заранее заполненный worklog с фактической длительностью работы.
Время учитывается только пока агент действительно работает: ожидание approval,
ответа пользователя или восстановления источника ставит таймер на паузу.

Для Codex CLI и Claude Code интерактивный approval включается явно в
`Настройки -> Интеграции`. После включения приложение устанавливает собственный
небольшой bridge в `~/.nool-notch/bin` и добавляет только свои записи в
существующие hook config. Перед первым изменением рядом создаётся файл с расширением
`.nool-backup`. Обмен между CLI и Nool идёт через Unix socket текущего
пользователя; сетевой сервис не используется. После первого запуска новой
версии приложения перезапусти уже открытые CLI-сессии, чтобы они подхватили
hooks. При выключении Nool удаляет свои hook-записи, не затрагивая чужие.

## PR/CI

Раздел `AI -> Inbox` определяет Git-репозиторий и текущую ветку по workspace
каждой AI-сессии. Если для неё найден PR/MR, справа в той же строке появляются
иконки CI, конфликтов, reviewer activity и переход к MR/PR. Code review
сохраняется для трёх уникальных недавно завершённых сессий, поэтому не исчезает
сразу после окончания работы агента. Для GitHub используется `gh`, для GitLab — `glab`.
Поддерживаются GitLab.com и self-hosted GitLab: хост берётся из remote самого
репозитория, поэтому отдельная настройка сервера в Nool не нужна.

При установке через Homebrew оба CLI устанавливаются автоматически. Открой
`Настройки -> Интеграции`: Nool проверит доступные хосты и предложит выполнить
однократную авторизацию в отдельном окне Terminal. При сборке из исходников CLI
можно установить вручную:

```sh
brew install gh
gh auth login

brew install glab
glab auth login --hostname gitlab.example.com
```

Nool не запрашивает и не сохраняет GitHub/GitLab-токены: авторизацией и её
хранением управляет соответствующий CLI. Данные обновляются при открытии панели
и затем раз в 30 секунд, пока панель видима.

## Сборка из исходников

Понадобятся Xcode или Xcode Command Line Tools со Swift 6:

```sh
git clone https://github.com/nail00749/nool_notch.git
cd nool_notch
./scripts/run-app.sh
```

Скрипт собирает executable, упаковывает его в `Build/NotchApp.app`, подписывает
и перезапускает приложение. По умолчанию используется локальный Apple
Development certificate. Если сертификата нет, временную ad-hoc подпись нужно
разрешить явно:

```sh
NOTCHAPP_ALLOW_ADHOC=1 ./scripts/run-app.sh
```

Ad-hoc переподпись может привести к повторному запросу Accessibility-доступа.
Для стабильной локальной подписи передай имя сертификата через
`NOTCHAPP_SIGNING_IDENTITY`.

## Разрешения и данные

- Accessibility используется как fallback для метаданных активного плеера.
- Calendar запрашивается только для показа ближайших событий.
- Jira-токен хранится в macOS Keychain.
- Закрепления Jira и визуальные настройки хранятся в `UserDefaults`.
- Существующая авторизация Claude Code читается только в памяти и не копируется
  в настройки приложения.
- Локальные события Agent Inbox используются только для текущего состояния и
  не записываются Nool в историю или логи.
- PR/CI читает только состояние текущего репозитория через уже авторизованные
  `gh` или `glab`; их credentials не копируются в приложение.
- Пароли, cookies и токены не должны попадать в репозиторий или логи.

## Разработка

- `Sources/NotchCore` — независимые модели квот.
- `Sources/NotchApp` — SwiftUI-интерфейс, провайдеры и AppKit-координатор окна.
- `Tests` — Swift- и shell-проверки.
- `scripts` — локальный запуск, подпись и упаковка релиза.
- `docs` — спецификации и планы развития.
- `CHANGELOG.md` — пользовательские изменения по версиям.

История изменений находится в [CHANGELOG.md](CHANGELOG.md), подробный контекст
для разработки — в [AGENTS.md](AGENTS.md), а пошаговая публикация релиза и
Homebrew cask — в [DEPLOY.md](DEPLOY.md).

## Релизы

Тег `vX.Y.Z` запускает GitHub Actions: workflow собирает arm64-приложение,
создаёт ZIP и SHA-256 checksum и публикует GitHub Release. Актуальные сборки
находятся на странице [GitHub Releases](https://github.com/nail00749/nool_notch/releases).
