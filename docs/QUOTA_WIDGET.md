# Виджет лимитов macOS

В сборках с командной подписью Apple Nool содержит настоящий WidgetKit widget
для рабочего стола и Центра уведомлений (macOS 14+).

## Добавление

1. Запустите собранное приложение хотя бы один раз.
2. На рабочем столе откройте контекстное меню → «Изменить виджеты».
3. Найдите **NotchApp → Лимиты Nool** и выберите маленький или средний размер.
4. Через «Изменить виджет» выберите период **5 часов** или **7 дней** и источник.
   В маленьком размере «Все» означает первый видимый источник; средний показывает
   до четырёх источников в порядке из настроек Nool → Лимиты.

Кольцо показывает **оставшийся** процент. Зелёный означает больше 20%, жёлтый —
до 20%, красный — до 10%. Серое кольцо с «—» означает отсутствие данных для
выбранного периода или необходимость входа в провайдер. Некоторые подписки
не имеют пятичасового окна — недельное значение не подставляется вместо него.

Значок часов означает старые данные: прошло 15 минут после снимка, наступило
время сброса или провайдер вернул stale. Виджет не предполагает, что после
времени сброса доступно 100%. Клик открывает текущие лимиты в Nool.

Оставляйте Nool запущенным. Когда виджет установлен, приложение проверяет
необходимость обновления и запрашивает видимые источники не чаще одного раза
в 5 минут через существующих провайдеров. При закрытии приложения остаётся
последний снимок. WidgetKit самостоятельно планирует перерисовку; мгновенное
обновление и точный пятиминутный интервал на рабочем столе не гарантируются.

## Сборка и подпись

Основное приложение остаётся Swift Package. `NoolWidgets.xcodeproj` содержит
только extension target и использует общие Foundation-модели из `NotchCore`.
`scripts/run-app.sh` собирает и вкладывает `.appex`, а `scripts/sign-app.sh`
подписывает расширение и приложение по отдельности одним сертификатом.

```sh
DEVELOPER_DIR=/Applications/Xcode-beta.app/Contents/Developer \
  NOTCHAPP_WIDGET_MODE=enabled ./scripts/run-app.sh
```

`NOTCHAPP_WIDGET_MODE`: `auto` (по умолчанию) включает виджет при наличии
выбранного сертификата Apple; `enabled` требует extension и подпись и при
невозможности завершает сборку с ошибкой; `disabled` исключает extension.

App Group имеет формат `<TEAM_ID>.com.nailuyltyev.NotchApp.widgets`. Скрипт
извлекает Team ID из публичного сертификата и записывает один идентификатор
в Info.plist и entitlements приложения/расширения. App Sandbox включён только
для extension; разрешения существующего приложения остаются прежними.

**Текущий `package-release.sh` намеренно выпускает ad-hoc сборки без виджета.**
Для публикации с WidgetKit нужен отдельный переход релизного процесса на
Developer ID, проверка подписи/App Group на другом Mac и нотариализация.
Наличие локального Apple Development сертификата не доказывает готовность
виджета к распространению через Homebrew. `NOTCHAPP_WIDGET_MODE=enabled`
с текущим ad-hoc релизным скриптом даст явную ошибку.

## Данные и проверки

App Group содержит только `quota-widget-v1.json`: идентификатор и название
провайдера, остаток, период, время сброса/обновления и состояние подключения.
URL аккаунта, сообщения провайдера, учётные данные и история AI не экспортируются.
Запись атомарная, права файла `0600`, чтение ограничено 64 КиБ; неподдерживаемая
версия или испорченный файл отображается как пустое состояние. Обычный выход
из приложения дожидается записи. Расширение не запускает CLI и не обращается
к API провайдеров.

```sh
DEVELOPER_DIR=/Applications/Xcode-beta.app/Contents/Developer \
  xcrun swift test --filter QuotaWidgetTests
Tests/Signing/sign-app.test.sh
```

Ручная проверка: добавить оба размера, изменить период/провайдера, сравнить
остатки с Nool, скрыть/переместить источник, кликнуть виджет, закрыть Nool и
проверить устаревание. Не путать успешную сборку с появлением в галерее или
фактическим обновлением WidgetKit.

Документация Apple: [Widget Extension](https://developer.apple.com/documentation/widgetkit/creating-a-widget-extension),
[App Groups](https://developer.apple.com/documentation/xcode/configuring-app-groups),
[обновление виджетов](https://developer.apple.com/documentation/widgetkit/keeping-a-widget-up-to-date).
