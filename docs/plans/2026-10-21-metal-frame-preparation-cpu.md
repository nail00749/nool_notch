# Стоимость подготовки кадров Metal

Статус: эксперимент не принят в рабочий код — устойчивое снижение общей
нагрузки не подтверждено. Ниже сохранены проверка гипотезы и результаты.

## Диагностика

Контрольный Release после фильтрации уведомлений экранов:
`8380ACAF-1A4B-311D-81A6-15BC4486262D`, PID 46579.
Свежий исходный замер дал среднее 19,97% CPU и медиану 19,3%; это ещё раз
показывает, что исторические 15,16% нельзя использовать вместо свежего контроля.

В `/tmp/nool-cpu-third-before.sample.txt` видны Metal draw, обновления SwiftUI,
фоновые опросы Accessibility/датчиков и чтение Agent Inbox. Sample содержит
ожидания IPC и диска, поэтому число попаданий не трактуется как CPU-процент.
Измерение CPU-времени потоков через `proc_pidinfo` за 15 секунд показало около
8% одного ядра у самого активного потока; оставшаяся работа распределена по workers.
Time Profiler снова не смог найти активный процесс для подключения.

Проверена гипотеза о запросах CLI-сессий: чтение редкого источника через общий
индекс действительно можно ускорить индексом источника. Но экономия около
2,8 мс раз в пять секунд составляет менее 0,1 процентного пункта всего процесса.
Эта правка не включена; запрос Codex Desktop при таком изменении замедлялся.
База исследовалась только для чтения, содержимое сессий не выводилось.

В Metal подтверждена другая лишняя работа: полный обход частиц и линий в
`isValid`, затем повторный обход и преобразование тех же полей в `prepare`.
Кроме того, в рабочем запуске собиралась подробная статистика каждого кадра,
хотя читали её только тесты.

## Проверенное экспериментальное изменение

Валидация элементов объединена с упаковкой GPU-буферов; преобразованные SIMD
значения используются повторно. Сохранены проверки границ количества,
конечности, положительных размеров и palette bucket. Дополнительно отклоняются
размеры, которые становятся нулём при преобразовании в Float, и невалидный
масштаб. Ошибочные кадры не запускают fallback, корректные последующие кадры
продолжают работать.

В production отключены подробные presentation callbacks, чтение GPU timestamps
и замер времени кодирования. Completion, освобождение занятых буферов и
обработка ошибок GPU обязательны и остаются включёнными. Нативные benchmark
и lifecycle-тесты явно сохраняют подробную статистику.

Шейдеры, алгоритм движения, плотность, 60 FPS, разрешение, цвета и курсор
не менялись. Контрольный executable сохранён для сравнения на том же пути app.

## Проверки

- Набор LiveWallpaper: 67 тестов, 3 opt-in проверки пропущены, ошибок нет.
- После дополнительной защиты Float: 12 focused-тестов валидации/lifecycle,
  ошибок нет. Проверены также освобождение слотов, native completion при
  отключённой телеметрии и последующий корректный кадр после ошибочного.
- Captures с включённой/выключенной телеметрией совпали побайтово.
- Отдельная проверка эталонного изображения на 1× и 2× прошла. Средняя ошибка
  RGB относительно SpriteKit-композиции — около 0,116 из 255, p99=1, максимум=3.
  Случайная сцена отличается от предыдущего эксперимента, поэтому разницу
  средних ошибок между отчётами нельзя выдавать за улучшение изображения.
- Независимое ревью проверило lifecycle GPU-буферов и обработку ошибок;
  замечание о Float underflow исправлено и покрыто тестами.

Нюанс диагностических счётчиков: если все слоты заняты, некорректный элемент
может учитываться как пропущенная занятая очередь до проверки содержимого.
На GPU он не отправляется и ошибкой GPU не считается.

Логи: `/tmp/nool-cpu-third-tests.log`, `/tmp/nool-cpu-third-final-tests.log`,
`/tmp/nool-cpu-third-visual.log`; снимки: `/tmp/nool-cpu-third-visual/`.

## Результат ABBA

Пользователь подтвердил плавность, курсор и открытый рабочий стол. Каждый
проход выполнен после перезапуска и 20 секунд прогрева, по 15 двухсекундным
отсчётам `top`, первый отсчёт исключён. Менялся executable на том же пути
bundle со стабильной подписью; настройки сохранили один и тот же хеш.

возвращён к `8380ACAF-1A4B-311D-81A6-15BC4486262D`. Кандидат сохранён только

## Диагностическое выключение обоев

По запросу пользователя показ обоев временно выключен через сохранённый
`enabled`, остальные настройки сохранены. На контрольном Release после
20 секунд прогрева получено 7,36% CPU в среднем, медиана 7,0%, диапазон
4,7–13,3% (15 интервалов). Это отключает не только GPU-сцену, но и её оверлеи
и feed метрик, поэтому разницу нельзя целиком приписать Metal.

Показ обоев затем включён обратно. Сериализация JSON упорядочила ключи, поэтому
сырой хеш данных после переключения может отличаться; значения настроек,
кроме временно изменённого `enabled`, не заменялись. Данные замера:
`/tmp/nool-metal-whole-app/wallpaper-off.json`.

Попытка системного Time Profiler закончилась ошибкой подключения к DTServiceHub,
а не отсутствием процесса NooL. Ограничение инструмента сохранено в
`/tmp/nool-cpu-third-system-trace.log`; разрешения системы не менялись.

## Второй отклонённый эксперимент: лишняя очистка кадра

Проверен `.dontCare` вместо `.clear` только при полном покрытии viewport первым
непрозрачным draw с консервативным запасом в 1 logical point. Частичное покрытие
сохраняло `.clear`. Пиксели совпали точно на 1×/2×; независимое ревью не нашло
риска неинициализированных пикселей.

Изолированный Release ABBA, одинаковый seed, 5120×1440, 60 FPS, 8 секунд
прогрева и 8 секунд измерения каждой фазы:

| Фаза | CPU renderer | Фактические показы/с |
| --- | ---: | ---: |
| Clear A1 | 5,33% | 59,20 |
| Skip B1 | 4,56% | 59,62 |
| Skip B2 | 6,07% | 59,75 |
| Clear A2 | 4,03% | 58,57 |

Все проверки cadence, dropped buffers и GPU errors прошли, но CPU не снизился:
средние 4,68% и 5,31% соответственно. Этот кандидат также отменён. Данные:
[clear ABBA](../benchmarks/metal-frame-preparation/clear-abba.json),
`/tmp/nool-metal-clear-tests.log`, `/tmp/nool-metal-clear-abba.log`.
Исходники эксперимента сохранены только в
`/tmp/nool-cpu-third-control/clear-candidate/`.

## Итог текущего исследования

Подтверждённого дополнительного снижения CPU не получено; обе экспериментальные
правки удалены из рабочего дерева. Запущен прежний проверенный Release,
живые обои включены, 60 FPS/плотность/эффекты восстановлены. Данные показывают
около 7,4% CPU при выключенном модуле обоев и около 4–6% у изолированного
renderer; суммировать их как точный профиль приложения нельзя — условия и
оверлеи различаются.

Instruments открыт также через GUI: тот же отказ DTServiceHub не позволяет
выбрать процесс для записи. Прямой диагностический запуск этой штатной службы
завершается SIGKILL; `codesign --verify` подтверждает корректную подпись на
диске. Причина завершения macOS не установлена, обход защит не применялся.
Другой установленной версии Xcode на машине не обнаружено. Следующее точное
ранжирование затрат требует рабочего профилировщика либо отдельной
инструментации компонентов, а не новых предположений по wall-time samples.
