# Полный Metal-прототип «Нейросети»

Дата: 21 октября 2026.

Это отчёт первоначального изолированного эксперимента. Последующая интеграция
в рабочие обои описана [отдельно](2026-10-21-metal-wallpaper-integration.md).

## Область эксперимента

`LiveWallpaperMetalPlexusView` и `LiveWallpaperPlexusSimulation` находятся в
`Sources/NotchApp/Features/LiveWallpaper/Prototype`. Рабочий renderer и настройки
не переключены: пользовательское приложение продолжает использовать прежний
SpriteKit с Metal-слоем линий.

Новый путь рисует градиент, свечения, частицы и связи одним Metal render pass
с тремя пакетами. SpriteKit в этом пути не участвует. Численная симуляция пока
выполняется на CPU, что позволяет сохранить исходные формулы и независимо
проверить выигрыш именно от замены рендера. MTKView — единственный источник
кадров; дополнительных таймеров нет. Три GPU-буфера не перезаписываются до
завершения команд. Ожидание GPU допускается только в явном offscreen snapshot,
не в живом рендере.

## Равенство входных данных

Оба backend получают один seed из новой настоящей SpriteKit-сцены: реальные
текстуры, положения, скорости, размеры, цвета и прозрачности. В A/B-прогонах
восстанавливается тот же seed, а не создаются разные случайные сцены.
Сохранены плотность, 60 FPS, ограничение частоты связей, реакция на курсор,
параллакс, сглаживание реакции на нагрузку и сброс часов после паузы.

SpriteKit хранит render-координаты как Float. Модель повторяет это округление
перед отрисовкой и построением связей, сохраняя исходную Double-арифметику движения.
Три модельных теста сравнивают 600 кадров с изменением энергии, курсора и
паузой, затем восстановление seed и повторную траекторию. Координаты, размеры
и связи совпадают точно; допуск RGB/opacity — 1e-6.

## Проверка изображения

Эталон — текущая рабочая композиция: замороженный SpriteKit-фон/частицы и
существующий Metal-шейдер линий. `scene.snapshot()` возвращает старые
SKShapeNode-линии и поэтому не используется как эталон нынешних живых обоев.
Оба backend заморожены; дополнительно проверяется отсутствие Scene updates
между снимками.

Результат на этой машине, RGB в шкале 0–255:

| Масштаб | Средняя ошибка всей сцены | p99 | Максимум |
| --- | ---: | ---: | ---: |
| 1× | 0,1972 | 1 | 3 |
| 2× | 0,1969 | 1 | 4 |

Без линий средняя ошибка 0,1855 / 0,1852 соответственно, p99=1, максимум=3.
Снимки визуально проверены. Это подтверждение для текущего GPU/macOS, не
обещание побитового равенства на любой видеокарте. В новом шейдере исправлен
неопределённый reversed-edge `smoothstep`; прежний shader-эталон оставлен без
изменения поведения, поэтому его переносимость — отдельный существующий вопрос.

## Методика CPU и плавности

Release XCTest создаёт отдельное click-through окно на самом широком экране.
Текущий renderer — настоящий SKView плюс существующий MetalLineView.
Кандидат — только MTKView и численная модель. Оверлеи и остальные функции
приложения не входят в этот изолированный тест.

Оба пути предварительно прогреваются по 8 секунд. Затем выполняется ABBA:
SpriteKit → Metal → Metal → SpriteKit, каждый раз тот же seed, 3 секунды
прогрева и 12 секунд измерения. CPU — сумма user/system времени процесса,
делённая на wall time, где 100% соответствует одному ядру.

Для SpriteKit измеряется частота завершённых обновлений сцены. Для Metal
проверяются и submissions, и реальные `drawable` presentations: более 55 FPS,
p99 presentation interval менее 35 мс, отсутствие GPU errors и dropped buffers.
У SpriteKit нет равнозначного публичного presentation callback в этом harness,
поэтому его update cadence не выдаётся за прямой замер показанных кадров.

## Результаты CPU

Два независимых Release-прогона ABBA на Odyssey, 5120×1440 при масштабе 1×,
160 частиц и целевых 60 FPS:

| Renderer | Средний CPU за четыре фазы | Диапазон CPU |
| --- | ---: | ---: |
| SpriteKit + Metal-линии | 10,12% | 6,00–14,55% |
| Полный Metal | 6,05% | 4,86–7,53% |

Средняя нагрузка изолированного рендера снизилась на 40,2%. Разброс заметный,
отдельные фазы пересекаются; это не гарантия такого же выигрыша в любой нагрузке
и не замер CPU всего NooL. Исходные результаты: [прогон 1](../benchmarks/metal-plexus/run-1.json),
[прогон 2](../benchmarks/metal-plexus/run-2.json).

SpriteKit завершал 59,71–60,06 обновления в секунду. Metal показывал
59,46–59,96 кадра в секунду, p99 интервала показа — 25 мс во всех фазах.
Ошибок GPU и dropped buffers не было. Редкие длинные интервалы остаются:
максимум Metal в автоматическом сравнении — 58 мс; абсолютное отсутствие
системных задержек эти результаты не доказывают.

Сохранённые изображения: [текущий renderer, 2×](../benchmarks/metal-plexus/spritekit-reference-2x.png),
[Metal-прототип, 2×](../benchmarks/metal-plexus/metal-prototype-2x.png).

## Живая проверка

В автоматическом ABBA сцена намеренно возвращается к одному seed между фазами,
а курсор фиксирован для сопоставимости. Именно это пользователь видел как
перезапуски и отсутствие реакции на мышь. Для отдельной проверки запущен
непрерывный Metal-preview с настоящим курсором, без переключения renderer и
повторной инициализации сцены.

Пользователь подтвердил: «Да, курсор работает, всё плавно». За 91 секунду
preview зарегистрировано 5442 показа и движение курсора; тест завершился
успешно и окно закрыто. Максимальный интервал показа при интерактивной проверке
составил 75 мс, поэтому субъективная плавность не означает отсутствие каждого
единичного длинного кадра.

Модельные тесты (3), сравнение изображений на 1×/2×, два Release ABBA и
непрерывный preview прошли. Это целевые проверки, полный набор тестов проекта
в рамках эксперимента не запускался. Независимое ревью проведено.

Прототип пока не подключён к рабочим обоям. Следующий этап — интеграция
существующего lifecycle (пауза, перекрытие, несколько мониторов, переподключение),
проверка fallback и повторный замер всего приложения в одинаковых условиях.

## Повторение эксперимента

```sh
DEVELOPER_DIR=/Applications/Xcode-beta.app/Contents/Developer \
  xcrun swift test --filter LiveWallpaperPlexusSimulationTests

NOOL_PLEXUS_VISUAL=1 \
DEVELOPER_DIR=/Applications/Xcode-beta.app/Contents/Developer \
  xcrun swift test --filter LiveWallpaperMetalPlexusPrototypeTests/testVisualComparison

NOOL_PLEXUS_BENCHMARK=1 \
DEVELOPER_DIR=/Applications/Xcode-beta.app/Contents/Developer \
  xcrun swift test -c release --filter LiveWallpaperMetalPlexusPrototypeTests/testNativeABBA

NOOL_PLEXUS_PREVIEW=1 \
DEVELOPER_DIR=/Applications/Xcode-beta.app/Contents/Developer \
  xcrun swift test -c release --filter LiveWallpaperMetalPlexusPrototypeTests/testInteractivePreview
```

Нативные эксперименты по умолчанию пропускаются. `NOOL_PLEXUS_SECONDS` меняет
длину измеряемой фазы, `NOOL_PLEXUS_OUTPUT` — каталог PNG/JSON (по умолчанию
`/tmp/nool-plexus-metal-prototype`). Окно теста временно перекрывает рабочий стол,
но не меняет настройки монитора, системные обои или предпочтения приложения.
Непрерывный preview работает до 180 секунд; файл `preview.stop` в каталоге
результатов позволяет завершить его раньше.

Логи: `/tmp/nool-plexus-simulation-tests.log`, `/tmp/nool-plexus-visual.log`,
`/tmp/nool-plexus-metal-benchmark.log`, `/tmp/nool-plexus-metal-benchmark-repeat.log`,
`/tmp/nool-plexus-metal-preview.log`.
