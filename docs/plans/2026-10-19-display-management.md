# Управление дисплеями — план

**Статус: текущий объём завершён 2026-10-20 по решению пользователя.**
Дальнейшее расширение фичи остановлено. Громкость/mute монитора, перехват
клавиш яркости и отложенная аппаратная яркость Odyssey не входят в закрытый
объём и требуют отдельного запроса. Непроведённые живые проверки перечислены
ниже и остаются ограничениями проверки, а не подтверждёнными сценариями.
Последняя проверка: сборка успешна; 1043 теста, 2 пропущены, ошибок нет.

Цель: базовое управление мониторами в духе BetterDisplay / Crisp прямо из
челки. Этап 1 использует только публичные API CoreGraphics; приватные
DisplayServices и DDC (IOAVService) — этап 2.

## Состояние реализации

- Реализованы этап 1, компактная чёрная панель с сеткой в две колонки и
  вертикальной яркостью, настройки и команды Launcher.
- Реализован этап 2: ленивые DisplayServices/IOAVService, чтение текущей
  аппаратной яркости, debounce записи 80 мс, последовательная очередь,
  двухсекундный timeout и переход на gamma при ошибке.
- Способ яркости выбирается в меню карточки. Прежние значения gamma и
  выбор программного затемнения сохраняются по UUID; аппаратная яркость
  при старте и выходе приложения не устанавливается.
- DDC на arm64 требует однозначного совпадения vendor/product/ненулевого serial.
  Метаданные ищутся на предках proxy или в полностью проверенной ветке с
  единственным внешним proxy. Неоднозначные и неполные результаты отклоняются.
- Проверено живое чтение: встроенный экран отвечает через DisplayServices;
  внешний успешно сопоставляется, но текущий IOAV-транспорт возвращает ошибку
  на DDC Get, поэтому используется gamma. Аппаратная запись не проверялась.
- Аппаратная яркость внешнего монитора отложена по решению пользователя.
  На Odyssey G95SC с прямым HDMI-подключением к MacBook (AppleDCPPS190)
  запросы IOAV возвращают `0xe0114000`; проверка при 60 Гц также не дала
  чтения DDC, исходные 120 Гц восстановлены. Проверенное изменение яркости
  в Crisp использует gamma; исходные яркость и цветовые таблицы восстановлены.
- Ручные сценарии ниже (реальные режимы, сон, переподключение, аппаратная
  запись) остаются приёмочной проверкой; unit tests не заменяют её.
- Реализованы включение/отключение экранов и отдельный режим расположения:
  перетаскивание с мягкой привязкой центров и краёв. Отключение
  требует подтверждения, расположение сохраняется сразу по «Применить».
  Последний независимый экран защищён от отключения.
- На текущем Mac проверено реальное отключение и включение Odyssey G95SC:
  выключенный экран остаётся доступным для восстановления. Также проверено
  изменение расположения и возвращение исходных координат обоих дисплеев.
  Исходные состояния и координаты восстановлены после проверок.
- Реализованы цветовые профили ColorSync и локальные именованные пресеты:
  создание, применение, переименование и удаление. Пресеты сохраняют семантику
  режимов и UUID, а не временные display ID; применяются с подтверждением за
  15 секунд и восстановлением конфигурации, профилей и яркости при отмене.
- На реальном HDMI-дисплее проверены смена на sRGB и возврат к заводскому
  профилю с восстановлением исходных профиля и gamma. Для ColorSync используется
  зарегистрированный ID профиля и проверка фактического выбора после записи.
- Проверен живой цикл пресета на двух экранах: сохранение, переименование,
  пробное применение, отмена и удаление временного набора. Исходные режимы,
  расположение, включённость и профили восстановлены.

Проверено на macOS 27.2 arm64: все нужные публичные и приватные символы
доступны (`IOAVService*`, `DisplayServices*Brightness`,
`SLSConfigureDisplayEnabled`, `CGVirtualDisplay*`).

## Структура

```
Features/Displays/
  DisplayModels.swift                // DisplayInfo, DisplayModeOption, ключ по UUID
  DisplayConfigurationService.swift  // единственная граница с CoreGraphics
  DisplayBrightnessService.swift     // gamma / DisplayServices / DDC (этап 2)
  DisplayFeatureModel.swift          // @MainActor, состояние + команды для UI
  DisplayRevertController.swift      // «Оставить режим?» + таймер отката
  DisplaysPanel.swift                // UI в челке
  DisplaySettingsView.swift          // раздел настроек
```

SwiftUI не обращается к CoreGraphics: view → `DisplayFeatureModel` → service.
Сервисы закрыты протоколами, чтобы тесты подставляли fake.

## 1. Список дисплеев и отслеживание изменений

- `CGGetOnlineDisplayList`, `CGDisplayIsBuiltin`, `CGDisplayIsMain`,
  `CGDisplayMirrorsDisplay`.
- Стабильный ключ для сохранения: `CGDisplayCreateUUIDFromDisplayID(id)`.
  `CGDirectDisplayID` может меняться после переподключения.
- Имя: `NSScreen.localizedName`, сопоставление через
  `deviceDescription[NSDeviceDescriptionKey("NSScreenNumber")]`.
- Изменения: `CGDisplayRegisterReconfigurationCallback`. В callback
  пропускать `.beginConfigurationFlag`, затем переходить на main actor.
  Можно и через `NSApplication.didChangeScreenParametersNotification`.

## 2. Режимы: разрешение, HiDPI, частота

```swift
let opts = [kCGDisplayShowDuplicateLowResolutionModes: true] as CFDictionary
let modes = CGDisplayCopyAllDisplayModes(id, opts) as? [CGDisplayMode] ?? []
```

- Фильтр `mode.isUsableForDesktopGUI()`.
- HiDPI: `mode.pixelWidth > mode.width`.
- Дедупликация по `(width, height, refreshRate, isHiDPI)`, без неё в списке
  будут дубли, отличающиеся только `ioFlags`.
- Текущий режим: `CGDisplayCopyDisplayMode(id)`.
- В UI группировать по «виду как» (`width×height`), частоту и HiDPI выбирать
  внутри группы.

## 3. Применение режима с откатом

```swift
var cfg: CGDisplayConfigRef?
CGBeginDisplayConfiguration(&cfg)
CGConfigureDisplayWithDisplayMode(cfg, id, mode, nil)
CGCompleteDisplayConfiguration(cfg, .forSession)   // пробный режим
```

- Перед применением запомнить предыдущий `CGDisplayMode`.
- `DisplayRevertController` показывает «Оставить? Откат через 15 с» по центру
  того же дисплея; координаты пересчитывать после смены режима.
- Подтверждение → повторно применить режим с `.permanently`.
  Таймаут или «Отменить» → вернуть предыдущий режим.
- Если дисплей отключили во время таймера, откат отменяется без ошибок.
- `CGError != .success` → показать ошибку и ничего не сохранять.

## 4. Главный дисплей и зеркалирование

- Сделать главным: в одной транзакции `CGConfigureDisplayOrigin(cfg, newMain, 0, 0)`,
  остальные дисплеи сдвинуть на `-origin` нового главного.
- Зеркалирование: `CGConfigureDisplayMirrorOfDisplay(cfg, id, master)`,
  выключение — `kCGNullDirectDisplay`.
- Те же изменения проходят через `DisplayRevertController`.

## 5. Программное затемнение (gamma)

```swift
CGSetDisplayTransferByTable(id, 256, red, green, blue) // исходные таблицы × factor
```

- Базовые таблицы брать из `CGGetDisplayTransferByTable` при старте, чтобы
  сохранить калибровку.
- При выходе вызывать `CGDisplayRestoreColorSyncSettings()`. macOS сбрасывает
  gamma после сна и смены профиля, поэтому значение применять повторно
  (`NSWorkspace.didWakeNotification`, screen parameters changed).
- Нижняя граница фактора около 0.1, чтобы экран не стал полностью чёрным.

## 6. Яркость (этап 2)

Приватные символы подгружаются лениво через `dlopen`/`dlsym`, без статической
линковки. Нет символа — возможность скрыта в UI.

**Встроенный экран** — `/System/Library/PrivateFrameworks/DisplayServices.framework/DisplayServices`:

```swift
typealias Get = @convention(c) (CGDirectDisplayID, UnsafeMutablePointer<Float>) -> Int32
typealias Set = @convention(c) (CGDirectDisplayID, Float) -> Int32
// "DisplayServicesGetBrightness" / "DisplayServicesSetBrightness"
```

**Внешний монитор, DDC/CI** — `IOAVServiceCreateWithService`,
`IOAVServiceWriteI2C`, `IOAVServiceReadI2C` из IOKit:

- Сервисы: обход IORegistry, класс `DCPAVServiceProxy` с `Location == "External"`.
- Сопоставление с `CGDirectDisplayID` — самая нетривиальная часть: сравнивать
  EDID/vendor/product/serial с `CGDisplayVendorNumber`, `CGDisplayModelNumber`,
  `CGDisplaySerialNumber` (см. `Arm64DDC.swift` в MonitorControl).
- Пакет записи:

```swift
// IOAVServiceWriteI2C(svc, 0x37, 0x51, &data, 6)
let data: [UInt8] = [0x84, 0x03, vcp, UInt8(v >> 8), UInt8(v & 0xFF), chk]
// chk = 0x6E ^ 0x51 ^ 0x84 ^ 0x03 ^ vcp ^ hi ^ lo
// VCP: 0x10 яркость, 0x12 контраст, 0x62 громкость
```

- Все DDC-вызовы вне main actor, на последовательной очереди, с timeout.
  Слайдер с debounce 50–100 мс, иначе часть мониторов зависает.
- DDC не отвечает → fallback на gamma-затемнение из пункта 5.

## UI

- Вкладка в челке: на каждый дисплей имя, слайдер яркости/затемнения и меню
  режимов.
- Команды Launcher: «Разрешение 1920×1080», «Главный дисплей …».
- Настройки: включение модуля, затемнение по умолчанию, восстановление режимов
  после переподключения (по UUID, в `AppPreferences`).

## 7. Включение и отключение экранов

- По запросу пользователя добавляется после этапов 1–2.
- Ленивые `SLSConfigureDisplayEnabled` и `SLSGetDisplayList` из SkyLight:
  отключённые дисплеи должны оставаться доступными для включения.
- Карточка выключенного экрана показывает «Включить» вместо режимов и яркости.
- Последний независимый экран отключить нельзя; зеркальный повторитель
  не считается отдельным оставшимся рабочим столом.
- Отключение требует подтверждения на оставшемся экране за 15 секунд.
- Восстановление сначала включает нужные экраны, затем возвращает режимы,
  расположение и зеркалирование. No-op переключения пропускаются.
- По умолчанию отключённые приложением экраны включаются при обычном выходе
  или отключении модуля; политика «Оставлять выключенными» сохраняет
  подтверждённое отключение. Для восстановления после перезапуска сохраняется метадата
  устройства; одного старого числового display ID недостаточно для совпадения.

## 8. Расположение дисплеев

- Кнопка «Расположение» открывает встроенную в панель схему экранов.
- Панель «Дисплеи» использует высоту 520 pt как для обычных карточек, так и
  для расстановки: данные двух экранов, схема и кнопки помещаются без прокрутки.
- Контуры экранов используют физические пропорции с учётом поворота; черновик
  и применяемые координаты остаются в системе координат рабочего стола CG.
- Перетаскивание меняет локальный черновик, экраны примыкают краями без
  пересечений и разрывов; координаты главного дисплея остаются `(0, 0)`.
- Во время перетаскивания центры и края соседних экранов притягиваются
  в пределах 8 pt на схеме; за пределами этой зоны движение свободное.
  Кнопки направлений убраны. Визуальная привязка переводится обратно в
  координаты рабочего стола, даже если физические пропорции отличаются от режима.
- «Применить» сохраняет все позиции одной постоянной транзакцией CoreGraphics
  без дополнительного подтверждения или таймера. При ошибке приложение пытается
  вернуть исходные координаты; при ошибке возврата сохраняет снимок для повтора.
  «Отмена» закрывает черновик без применения.
- При изменении состава или параметров дисплеев черновик сбрасывается;
  зеркальные повторители следуют за своим главным дисплеем.

### Политика сохранения отключения — реализовано

Выбираемая политика восстановления: **включать при выходе** (по умолчанию)
или **оставлять выключенными** до явного включения в NooL. Подтверждённое
намерение хранится отдельно от журнала временных изменений и чужих отключений.
При работающем модуле оно повторяется после запуска, пробуждения или
переподключения, только если остаётся другой доступный физический экран.
При потере всех реальных выходов известный принадлежащий NooL дисплей временно
включается для восстановления доступа; карточка объясняет это состояние.
Проверены 23 теста политики и 12 интеграционных тестов; полный набор:
1043 теста, 2 пропущены, ошибок нет. Внутренние проверки питания не перечисляют
каталог разрешений повторно; проверки UUID и аппаратной идентичности сохранены.
На Odyssey G95SC проверены подтверждённое отключение, завершение сессии без
включения, чтение сохранённого намерения новым экземпляром сервиса, временное
включение, повторное отключение после сброса wake-попыток и явное включение
с очисткой намерения. Исходные HDR, режимы, расположение, профили, gamma,
яркость и питание восстановлены. Проверка использовала отдельное хранилище
и аварийное восстановление с таймером 20 секунд. Весь сценарий занял 42 секунды:
проверки после временного включения могли пересечься с аварийным восстановлением,
поэтому не считаются изолированным доказательством wake-сценария. Настоящий
перезапуск macOS и физическая потеря всех выходов не проверялись.
До запуска NooL состояние определяет macOS.

### Итоги этапов и отложенные идеи

1. Цветовые профили и пользовательские наборы настроек — реализованы.
2. Коррекция изображения и Keep Awake — реализованы.
3. Системные переключатели: Dark Mode, Night Shift, True Tone, автояркость — реализованы. Проверены живые переключения и возврат исходных значений на macOS 27.2 / MacBook M2 Pro. Драйверы выполняются последовательно вне main actor с watchdog; неизвестный ABI или отсутствующие символы означают недоступность. Это внутренние API macOS, совместимость других версий и моделей отдельно не подтверждена.
4. HDR и Extra Brightness — реализованы с проверками совместимости; системные
   пресеты Apple и Smooth scaling — реализованы. Проверено 973 теста (2 пропущены),
   оба раскрытых экрана помещаются в 500×380 без прокрутки. Установка Smooth
   Scaling в /Library и системный запрос администратора требуют отдельной живой
   проверки на экране без чужого override; существующая настройка Odyssey не менялась.
5. Cross Unaligned Edges и политика длительного отключения — реализованы.
6. Громкость монитора — отложена за пределы закрытого объёма. Возвращаться
   к ней или диагностике DDC-яркости Odyssey только по новому запросу.

Вне списка со скриншота остаётся прежняя идея перехвата клавиш яркости
(требует отдельного исследования разрешений). Smooth scaling использует
физические HiDPI override-режимы; виртуальные дисплеи в эту функцию не входят.
