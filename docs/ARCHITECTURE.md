# Структура NooL App

## Каталог и жизненный цикл модулей

`App/Modules/AppModuleStore` хранит доступность встроенных функций отдельно от
их настроек. Неизвестные идентификаторы выключенных модулей сохраняются, чтобы
переключение между версиями приложения не теряло выбор. Отсутствующая настройка
означает прежний набор возможностей. Launcher и основные настройки — постоянная
оболочка; пустой набор функциональных модулей допустим.

`AppModuleRuntime` запускает зарегистрированные владельцем функции один раз и
останавливает их при выключении. При смене набора сначала выполняются остановки,
потом запуски. Изменения каталога доставляются после обновления состояния, чтобы
подписчики не читали старое значение `@Published`. Повторный запуск функций
использует обратимую остановку; terminal shutdown остаётся отдельным действием.
UI скрывает команды и панели, но владельцы дополнительно проверяют доступность
перед действием и отсекают поздние callbacks. Настройки, Keychain и история не
сбрасываются. Размещение продолжает принадлежать функциональным coordinators.

Это runtime-каталог встроенных функций. Он не загружает сторонние библиотеки и
не меняет SwiftPM target boundaries автоматически.

Проект остаётся Swift Package с тремя production targets: `NotchCore`,
`NotchApp` и `NoolAgentBridge`. Папки внутри `NotchApp` обозначают ответственность,
а не отдельные Swift-модули: доступность типов и API приложения не меняется.

`NoolWidgets.xcodeproj` — отдельный WidgetKit extension target, встраиваемый
в подписанный app bundle. Он компилирует общие DTO из `NotchCore` и читает
ограниченный снимок через App Group. Providers, авторизация и обновление
остаются у `QuotaFeatureModel`; `QuotaWidgetPublisher` владеет фоновой записью
и запросами reload WidgetKit. Подробности: [виджет лимитов](QUOTA_WIDGET.md).

## Границы ответственности

- `App` собирает приложение и связывает функции. Только соответствующий
  coordinator меняет геометрию своего окна; `NotchWindowCoordinator` остаётся
  единственным владельцем внешнего frame челки.
- `Features` владеет поведением своей функции: моделями, клиентами, провайдерами
  и UI. Протоколы `CalendarProviding`, `JiraProviding`, `NowPlayingProviding`
  живут в своих функциях, а не в общем контейнере протоколов.
- `Shared` содержит код без зависимости от конкретной функции. Он не знает о
  Jira, Launcher, Agent Inbox или `NotchViewModel`. `NotchCore` остаётся отдельным
  Foundation-only target; AppKit/SwiftUI helpers туда не переносятся.
- Межфункциональные сценарии уже существуют: Launcher использует AIChat,
  Calendar, WindowLayouts и Workspaces; Dock показывает данные нескольких функций.
  Перенос по папкам не объявляет эти зависимости устранёнными.
- `Workspaces` хранит наборы и запускает их через собственный opener; применение
  раскладки делегируется `WindowLayoutManager` через callback из Launcher.
  `QuotaAlertPolicy` определяет пороги без UI, а `QuotaAlertController` владеет
  настройками, дедупликацией и доставкой системных уведомлений.
- `Resources` остаётся в прежнем месте: SwiftPM обрабатывает его через
  `.process("Resources")`; имя bundle и способы загрузки ресурсов сохраняются.
- `LidEffectController` связывает отдельные протоколы датчика, разрешения и
  рендера. Синхронные HID-запросы выполняются на одной фоновой очереди,
  сохраняемой между включениями; UI ограничивает ожидание первого показания
  двумя секундами. Системный вызов не отменяемый: поздний результат игнорируется,
  ресурсы закрываются после его возврата, новые параллельные чтения не создаются.
  ScreenCaptureKit исключает окна NooL App и передаёт кадры локальному Core Image
  renderer. Наложение владеет своим click-through NSPanel только на встроенном
  экране. Настройки не запрашивают доступ автоматически; отключение, сон и
  устаревшие данные гасят наложение, generation checks отсекают поздние callbacks.

## Что уже вынесено в Shared

`TextEditingAction` разбирает и выполняет стандартные команды редактирования
в панелях и Dock. `TextEditingPanel` маршрутизирует их к активному editor.
`UtilityPanel` задаёт общие стиль и настройки служебных окон; показ, размеры,
закрытие и отмена операций остаются у функциональных coordinators.

`SecurityScopedResource` балансирует начало и завершение доступа к URL. Полка
и файловые операции удерживают ресурс на время работы. Он не решает, разрешено
ли переименование или чтение файла: эти проверки остаются у соответствующей
операции. Палитра, signal colors и стиль кнопок также используются из Shared.

## Правила дальнейшего выделения

Новый общий тип должен иметь конкретных потребителей и одинаковую семантику.
Начинайте с локального кода функции; переносите в Shared, когда повторяется
поведение, а не только несколько похожих строк. Не создавайте общий `Utils.swift`.

CLI-процессы пока остаются у своих провайдеров: у потокового чата, auth probe,
квот и PR/CI разные протоколы, лимиты вывода и отмена. Их объединение требует
отдельной проверки жизненного цикла процессов. Аналогично, форматы дат Jira,
квот и календаря не объединяются одним неявным парсером.

## Владельцы состояния и окон

`NotchViewModel` связывает функции, управляет выбором панелей, сворачиванием,
transient surfaces и межфункциональными действиями. Он предоставляет экранам
прежний интерфейс, делегируя состояние и команды отдельным владельцам:

| Владелец | Ответственность |
| --- | --- |
| `Features/Quotas/QuotaFeatureModel` | Снимки квот, настройки представления, порядок провайдеров и обновление |
| `Features/Calendar/CalendarFeatureModel` | События, месячный кэш, напоминания и подписки календаря |
| `Features/CodeReview/CodeReviewStore` | Состояния PR/CI, polling, дедупликация запросов и счётчики новой активности |

Каждый объект владеет своими асинхронными задачами. Корневая модель передаёт
их `objectWillChange` экранам, а при завершении приложения вызывает `stop()`.
Отмена задач и проверки актуальности не дают запоздалым ответам восстановить
остановленное состояние. Задачи не удерживают владельцев на время ожидания.

`NotchWindowCoordinator` владеет окном челки, его геометрией, выбором дисплея
и жизненным циклом дочерних координаторов:

- `Features/Quotas/Presentation/QuotaEdgeWindowCoordinator` — боковые окна
  лимитов, hover и анимации появления.
- `Features/Quotas/Presentation/QuotaStackWindowCoordinator` — угловой стек
  лимитов, окна карточек и их анимации.
- `App/Settings/SettingsWindowCoordinator` — окно настроек.

Дочерние координаторы поддерживают `start()` / `stop()`; остановка скрывает
окна и отменяет отложенные действия. Координаторы квот также инвалидируют
завершения старых анимаций. Остановка корневого координатора и модели является
терминальной и используется при выходе из приложения. Геометрией каждого окна
управляет только его владелец; инварианты челки и popover остаются в `AGENTS.md`.

## Проверка после переноса

SwiftPM автоматически находит Swift-файлы внутри target, поэтому отдельные
списки исходников не нужны. Запускайте `swift build`, `swift test` и
`git diff --check`; при изменении размеров, фокуса или hover дополнительно
проверяйте AppKit-сценарий. Старые документы в `docs/superpowers` сохраняют
исторические пути; текущая карта — этот файл и `AGENTS.md`.
